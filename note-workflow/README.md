# note 記事量産 自動化ワークフロー

300円note（AI活用 × 知的生産／副業ジャンル）を、リサーチから告知文まで**毎朝自動で1周ぶん生成**するパイプライン。
人が触るのは最後の「公開ボタン」だけ、を目指す構成です。

## 6役割 = パイプラインの6ステージ

| # | 役割 | 入力 | 出力 | 自動化 |
|---|------|------|------|--------|
| 01 | リサーチ | Web（note人気/急上昇・X反応・公式レポート） | 売れ筋テーマ候補 + スコア | ✅ 完全 |
| 02 | 企画 | 01の結果 + 過去実績ログ | 次に書くテーマ10本 | ✅ 完全 |
| 03 | 執筆 | 採用テーマ1本 | 4,000字・無料/有料境界設計済み記事 | ✅ 完全 |
| 04 | 検品 | 03の原稿 | AIっぽさを消した1人称原稿 | ✅ 完全 |
| 05 | デザイン | テーマ・タイトル | 表紙10案＋告知画像の生成指示書 | ✅ 指示書まで |
| 06 | 営業 | 完成記事・タイトル | X告知30本 + 予約投稿用CSV | ✅ 生成まで |

各ステージの指示（システムプロンプト）は `0X-*/prompt.md` にある。
`RUN.md` が全ステージを順に実行するオーケストレーション定義。

## 毎朝の自動実行（Routine）

この環境（Claude Code on the web）自体を毎朝スケジュール起動し、`RUN.md` を実行させる。
外部LLMのAPIキーは不要（この環境のClaudeが実行者）。

- 生成物は `output/YYYY-MM-DD/` に保存し、ブランチにコミット。
- あなたは朝、`output/今日/` を見て公開判断するだけ。

セットアップは「② 自動実行の入れ方」を参照。

## "売れてる"の推測ロジック（数字が無くても抽出する）

noteは記事ごとの販売実数を公開しない。よって**公開シグナルの合成スコア**で代替する。
詳細ルーブリックは `01-research/scoring.md`。要点：

```
sellability_score =
    0.35 * スキ数の相対順位（ジャンル内）
  + 0.20 * 人気/急上昇タブ掲載
  + 0.15 * X上の「買った/良かった」言及数
  + 0.15 * 有料 かつ 価格が300〜980円レンジ（衝動買い帯）
  + 0.10 * 著者フォロワー数（供給者の実績）
  + 0.05 * 直近30日の投稿である（鮮度）
```

さらに「**1年後も売れるか**」を判定する耐久フィルタ（`01-research/scoring.md` の durability チェック）を通し、
一過性トレンド（特定ツールの一時的バズ等）を除外する。

## 手動でも回せる

Routineを使わず、この環境に「`RUN.md` を実行して」と言うだけでも1周まわる。
個別ステージだけ回したい時は各 `0X-*/prompt.md` を単体で使う。

## ディレクトリ

```
note-workflow/
├── README.md              ← これ
├── RUN.md                 ← 全ステージ オーケストレーション定義
├── 01-research/  prompt.md scoring.md
├── 02-planning/  prompt.md
├── 03-writing/   prompt.md
├── 04-qa/        prompt.md
├── 05-design/    prompt.md
├── 06-sales/     prompt.md
└── output/YYYY-MM-DD/     ← 毎朝の生成物（自動作成）
```

## 正直な制約

- **note公開API無し**：完全自動投稿はできない。安全策は「下書きコピペ→公開は手動」。
  どうしても自動化するならPlaywrightでログイン済みセッション操作だが note規約 に抵触しうるため非推奨。
- **X予約投稿**：X API（有料）かブラウザ自動化が要る。標準では `06-sales/` が**予約用CSV**を出力し、
  SocialDog等のツールに読み込ませる運用を推奨。
- **売上実数は取得不可**：上記スコアは"推測"。実績は自分の販売データ（`02-planning/history.csv`）で補正していく。
