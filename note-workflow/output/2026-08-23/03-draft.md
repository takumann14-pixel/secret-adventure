# AIが書いた文章、なぜ「読む気が失せる」のか

## フック

AIに書かせた4,000字を読み返したとき、多くの方が違和感を覚えるのではないでしょうか。内容は間違っていない。構成も整っている。それなのに、なぜか読む気が失せてしまうのです。

## 共感と自己開示

私も同じ経験をしました。生成AIを使い始めた頃、私は毎日のように記事を量産していたと言えるでしょう。しかし、公開しても反応がほとんどありませんでした。スキは3つ、そのうち2つは知り合いだったのです。

様々な原因が考えられますが、最も重要なのは文章の質だと考えられます。私はその後、自分の原稿を1文ずつ読み返す作業を続けました。そして、AIが書いた文章には共通した症状があることに気づいたのです。

## 結論の予告

この記事では、AIっぽさの正体を8つの症状に分解します。そして、それぞれをどう直すかを、置換前と置換後の実例つきで示します。読み終えたとき、あなたは自分の原稿のどこが「AIっぽい」のかを、自分で見つけられるようになるでしょう。

## 全体像

まず、症状1を無料で完全に公開します。次に、有料パートで残りの7症状と、私が実際に使っているチェックリストをお渡しします。最後に、つまずきやすいポイントについても触れていきます。

## 症状1：「〜ではないでしょうか」問題（無料公開）

AIっぽさの最大の犯人は、断定を避ける語尾です。

具体的には、「〜ではないでしょうか」「〜と言えるでしょう」「〜かもしれません」といった表現が挙げられます。これらは一見丁寧ですが、読者にとっては「で、結局どっちなの」というストレスになります。

なぜAIはこれを多用するのでしょうか。それは、AIが断定によるリスクを回避するように訓練されているからです。しかし、読者が有料記事に求めているのは、書き手の判断です。保険をかけた文章に、人はお金を払いません。

置換のルールは単純です。

- 「〜ではないでしょうか」→ 「〜だ」
- 「〜と言えるでしょう」→ 削除するか「〜だと思う」
- 「〜かもしれません」→ 本当に不確かな時だけ残す

実例を示します。

**Before：** 冒頭の一文が重要ではないでしょうか。読者は最初の数行で読むかどうかを判断していると言えるでしょう。

**After：** 冒頭の一文で全部決まる。読者は3行目までに帰るか残るかを決めている。

情報量は同じです。しかし、後者には書き手がいます。前者にはいません。

まずはこの1つだけでも、今日の原稿に適用してみてください。効果的だと感じられるはずです。

<!-- 💰 有料境界 -->

ここから先は、私が実際に自分の原稿で潰してきた残り7つの症状と、その置換ルールの全てです。

## 症状2：空カロリー語

「重要です」「様々な」「効果的です」「多岐にわたる」。これらは意味を持っているように見えて、実際には何も言っていません。

対処法は、その語を具体に置き換えることです。「重要です」と書いたら、「なぜ重要か」を一段掘って書き直します。

**Before：** 冒頭は非常に重要です。
**After：** 冒頭で離脱した読者は、二度と戻ってこない。

## 症状3：三点セット構文

「まず」「次に」「最後に」の機械的な反復です。構造は分かりやすいのですが、3つ揃うと途端に教科書っぽくなります。

対処法は、3つのうち1つを崩すことです。「まず」を消して、いきなり本題から入る。あるいは「最後に」を「で、いちばん効いたのはこれです」に変える。

## 症状4：主語の消失

AIは一般論を書くのが得意です。しかし有料noteで読まれるのは、書き手個人の話です。

「一般的に、継続が大切だと言われています」という文には誰もいません。「私は3ヶ月で挫折した」には人がいます。主語が消えている段落を見つけたら、「私は」を戻してください。

## 症状5：文長の均一化

AIの文章は、1文の長さが揃いすぎています。40字前後の文が延々と続くと、読者は催眠状態になります。

対処法は、短文を混ぜることです。特に、いちばん言いたい一行は10字以内にします。

たとえばこうです。「読者は飽きている。」——これだけで、リズムが変わります。

## 症状6：保険表現

「場合によっては」「一概には言えませんが」「個人差はありますが」。これらは全部削っても、文の意味は変わりません。むしろ強くなります。

有料記事では、書き手が責任を取る姿勢そのものが商品です。保険をかけるほど、商品価値は下がります。

## 症状7：装飾の過剰

絵文字、太字、箇条書き。AIはこれらを大量に使います。読みやすくしているつもりで、実際には地の文の力を削いでいます。

目安として、箇条書きは1記事に3箇所まで。それ以上は、地の文の語りに戻せないか検討してください。

## 症状8：締めの空洞化

「いかがでしたか」「ぜひ試してみてください」「参考になれば幸いです」。これらは何も指示していません。

締めでは、読者がやることを1つだけ、具体的に指定します。「今日書いた原稿を開いて、『でしょうか』で検索してください」のように。

## つまずきポイント

この作業を始めると、多くの人が2つの壁にぶつかります。

1つ目は、直しすぎて自分の文章が壊れることです。8症状を全部一度に潰そうとすると、原稿がバラバラになります。私のおすすめは、1回の推敲で症状を2つまでに絞ることです。

2つ目は、直したのにまだAIっぽいと感じるケースです。この場合、原因は言い回しではなく構成にあります。具体的には、書き手自身の失敗が1つも書かれていないことが多いです。成功例だけの記事は、どれだけ言い回しを直してもAIっぽさが残ります。

## チェックリスト

- [ ] 「でしょうか」で検索 → 全部断定に変える
- [ ] 「重要」で検索 → 具体に置換
- [ ] 「まず」で検索 → 3点セットになっていないか確認
- [ ] 「一般的に」で検索 → 「私は」に書き換え
- [ ] 一番言いたい段落 → 短文が1つも無ければ追加
- [ ] 「場合によっては」で検索 → 削除
- [ ] 箇条書きの数を数える → 4箇所以上なら地の文に戻す
- [ ] 最終段落 → 読者への具体的な指示が1つあるか
